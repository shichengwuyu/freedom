## 用途

把 novel 工作台后半段（剧本→成片）建模成一条「多节点 + 用户可见 + 可单步干预」的工作流。借鉴小云雀"多 Agent 协同 + 用户可见流水线"的范式，但保持 Freedom 现有的节点级编辑能力，每个工作流节点都暴露统一的「状态机 + 操作」。

本能力是配音节点、字幕节点、合成节点的「编排底座」——它们都通过本能力的工作流节点机制对外暴露。

## ADDED Requirements

### Requirement: 工作流节点图

系统必须为「剧本→成片」整条链路定义一份声明式的工作流节点图。节点图至少包含以下 9 个节点，按依赖顺序：

1. 剧本节点（已有）
2. 分镜剧本节点（已有）
3. 资产节点：角色（已有）
4. 资产节点：场景（已有）
5. 资产节点：道具（已有）
6. 镜头视频节点（已有，升级为可挂载配音 / 字幕的复合节点）
7. 镜头配音节点（新增）
8. 镜头字幕节点（新增）
9. 成片合成节点（新增；BGM 选曲 + ffmpeg 合成 + 输出分享都归到这一个节点下）

#### 场景：用户从 UI 上看到全部 9 个节点

- **当** 用户打开 novel 工作台
- **那么** 顶部工作流图横向显示 9 个节点，每个节点展示当前状态徽标（未启动 / 排队中 / 进行中 / 成功 / 失败 / 跳过 / 已取消）

#### 场景：节点之间用箭头显示依赖

- **当** 工作流图渲染时
- **那么** 节点之间用箭头连接，箭头从上游指向下游；下游节点灰显表示"等上游成功后才能跑"

### Requirement: 节点统一状态机

系统的每个工作流节点必须遵循统一的状态机：`未启动 → 排队中 → 进行中 → （成功 / 失败 / 跳过 / 已取消）`；其中"失败 / 跳过"可被重试回到"排队中"。

#### 场景：节点启动进入排队态

- **当** 用户点击某节点的「开始」按钮
- **那么** 节点状态立即从「未启动」变成「排队中」，3 秒内进入「进行中」（取决于 worker 池空闲度）

#### 场景：节点成功完成

- **当** 节点对应的后端任务返回成功
- **那么** 节点状态变成「成功」，工作流图实时刷新

#### 场景：节点失败保持可重试

- **当** 节点对应的后端任务返回失败
- **那么** 节点状态变成「失败」，「重试」按钮亮起；下游节点保持「未启动」或「等待重试上游」态，不会盲目接着跑

#### 场景：用户主动停止节点

- **当** 用户点击某节点的「停止」按钮
- **那么** 节点状态变成「已取消」；后端 worker 收到 abort 信号，子进程被 kill

### Requirement: 节点依赖自动推进

工作流图必须支持"上游成功后自动启动下游"模式（也支持"全部手动单步跑"模式，用户可切换）。

#### 场景：自动模式下上游成功自动启动下游

- **当** 工作流跑在「自动模式」下，且上游节点变成「成功」
- **那么** 所有直接依赖它的下游节点自动从「未启动」变成「排队中」

#### 场景：上游失败时下游进入等待态

- **当** 工作流跑在「自动模式」下，且上游节点变成「失败」
- **那么** 下游节点保持「未启动」态，但 UI 上明确显示"等上游重试"

#### 场景：手动模式下用户逐个启动

- **当** 工作流跑在「手动模式」下
- **那么** 即使上游成功了，下游节点也不会自动启动；用户必须手动点每个节点的「开始」

### Requirement: 单步介入编辑

任意一个工作流节点的「成功」结果必须支持用户介入修改，修改后节点重新进入「进行中」态跑一遍（而不是从整个工作流重启）。

#### 场景：配音节点介入编辑后重跑

- **当** 用户在「镜头配音节点」成功的状态下，调某个镜头的音色并点「重新生成」
- **那么** 仅该镜头对应的配音子任务重跑，其他镜头的配音不重跑；整个配音节点保持「成功」态

#### 场景：字幕节点介入编辑后重跑

- **当** 用户在「镜头字幕节点」成功的状态下，编辑某行字幕文字
- **那么** 该镜头的字幕时间轴立即更新（纯数据变更，不调模型），「重生成最终字幕文件」按钮可一键重新编译 srt

### Requirement: 工作流刷新恢复

工作流任务的所有节点状态必须持久化到后端，刷新 / 切换页面 / 关闭后重开时自动恢复。

#### 场景：刷新后节点状态保留

- **当** 用户在工作流跑到一半时刷新页面
- **那么** 刷新回来后每个节点的状态徽标和进度数字与刷新前一致

#### 场景：多设备同步

- **当** 登录用户在设备 A 启动了工作流，换到设备 B 打开同一项目
- **那么** 设备 B 看到的工作流图与设备 A 完全一致（状态、进度、节点都同步）

### Requirement: 工作流任务状态总览

novel 工作台顶部必须显示一个工作流「总体状态」徽标，聚合当前所有节点状态得出：「未启动 / 进行中 / 已完成 / 部分失败 / 已停止」。

#### 场景：总体状态根据节点聚合

- **当** 用户查看 novel 工作台顶部
- **那么** 总体状态徽标显示：所有节点都未启动 → 「未启动」；有节点进行中 → 「进行中」；所有节点都成功或跳过 → 「已完成」；有节点失败但其他都成功 → 「部分失败」；有节点被停止 → 「已停止」
